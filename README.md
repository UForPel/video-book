# 영상책 (Video Book)

유튜브 영상을 앱 안에서 재생하면서, 영상의 자막과 정리된 글을 함께 읽을 수 있는 개인용 모바일 우선 웹앱 프로젝트입니다.

## 프로젝트 목표

- 스마트폰 브라우저에서 편하게 사용하는 개인용 웹앱
- 영상 검색과 재생, 시간대별 자막 읽기를 한 화면에서 제공
- 자막의 오탈자·띄어쓰기·문장부호를 편집해 읽기 좋은 글로 정리
- 가능하면 GitHub Pages에서 정적 웹앱으로 운영

## 개발 원칙

1. 무료 또는 거의 무료로 운영합니다.
2. 외부 유료 API와 유료 AI에 핵심 기능이 의존하지 않도록 합니다.
3. 무료 서비스라도 사용량·쿼터 제한이 있으면 핵심 의존성으로 채택하기 전에 확인합니다.
4. 가능한 작업은 서버 대신 브라우저 안에서 처리합니다.
5. Android 스마트폰에서 실제로 테스트합니다.
6. 유튜브의 공식 기능과 이용약관을 우선 검토하고, 비공식 연동은 안정성·정책 위험을 확인합니다.
7. 기존 ReadTube 프로젝트의 코드와 경험을 참고하되, 기존 저장소는 보존합니다.

## 최우선 제품 목표 — 반드시 지킬 사용자 흐름

영상책의 핵심 가치는 사용자가 YouTube 모바일 웹과 영상책 사이를 오가며 대본을 복사하지 않아도, 영상책 안에서 스크립트를 읽고 교정된 형태로 볼 수 있게 하는 것입니다.

1. **영상책 페이지 안에서 YouTube 영상 검색**
2. 검색 결과에서 영상을 선택하고 영상책 안에서 재생
3. 선택한 영상의 자막/스크립트를 가능한 범위에서 자동 추출
4. 추출한 스크립트의 맞춤법·띄어쓰기·문장부호를 교정
5. 교정된 스크립트를 영상책 페이지 안에 표시 (시간 정보가 있으면 재생과 동기화)

**금지되는 제품 흐름:** 사용자가 YouTube 모바일 웹에서 대본을 직접 복사해 영상책에 붙여넣도록 요구하는 방식. 사용자가 이미 모바일 웹에서 대본 복사가 어렵다고 명확히 설명했으므로, 이를 해결책으로 다시 제안하지 않습니다.

**기술적 현실:** 검색, 자막 추출, 교정은 서로 다른 단계이며 각각 독립적으로 검증합니다. 공식 YouTube API로 임의 공개 영상의 자막 본문을 일반 시청자 권한으로 가져올 수 있다고 가정하지 않습니다. 비공식 내부 API, 스크래핑, 접근 제한 우회는 구현하지 않습니다. 현재 조사 범위에서 이 조건들을 모두 충족하는 자동 추출 경로는 아직 확인되지 않았으므로, 이 핵심 기능은 미해결이며 프로젝트의 성공 여부를 결정하는 선결 과제입니다.

YouTube 공식 대본 페이지 링크는 보조 링크일 뿐, 영상책 내부 자동 추출·교정·표시 기능의 대체물이나 완료로 간주하지 않습니다.

## 기술적 주의사항

- GitHub Pages는 정적 파일 호스팅이며 백엔드 서버가 아닙니다.
- YouTube Data API에는 쿼터가 있으므로 사용량 제한 없는 검색 수단처럼 취급하지 않습니다.
- YouTube 공식 API는 임의의 모든 영상 자막을 자유롭게 가져오는 범용 API가 아닙니다.
- YouTube 임베드 영상의 임의 프레임을 브라우저 캔버스로 추출하는 데는 교차 출처 제한이 있습니다.
- 브라우저 내 음성 인식·AI 처리는 기기 성능과 메모리 한계를 Android에서 검증해야 합니다.
- API 키, 비밀번호, 개인 정보는 공개 저장소에 올리지 않습니다.

## YouTube 공식 대본 대체 경로
- 영상 링크를 불러오면 해당 영상의 YouTube 시청 페이지로 연결되는 **YouTube에서 공식 대본 보기** 링크가 표시됩니다.
- YouTube 도움말에 따르면 자막이 있는 영상은 영상 설명의 '대본 보기'에서 전체 대본을 확인하고, 각 문장을 눌러 해당 시점으로 이동할 수 있습니다.
- 이 링크는 YouTube 공식 페이지로 이동하는 보조 경로입니다. 대본 내용을 영상책 패널로 자동 가져오거나 동기화하지는 않습니다.
- 영상책 내부 자막 패널은 현재 범용 자동 취득이 미해결입니다. 제작자 제공/허가 SRT/VTT는 일반 시청자용 해결책이 아니며 특수 권한 테스트 참고로만 취급합니다.


## 참고 기록: 제작자 권한 자막 파일 경로 (일반 시청자용 해결책 아님)
이 경로는 일반 유튜브 시청자가 사용할 수 있는 방법이 아니다. 제작자 또는 영상 편집 권한이 있는 사람이 SRT/VTT 파일을 따로 제공하고, 공개 저장소 재배포 권한까지 확인해야 한다. 따라서 **영상책의 일반 시청자용 기능이나 핵심 해결책으로 요구·안내하지 않는다.**

과거 검토한 정적 등록 구조는 권리 허가가 명확한 파일을 내부 테스트할 때만 쓸 수 있다. 사용자가 제작자에게 연락하거나 Studio 파일을 받아오도록 요구하지 않는다. 이 경로는 앱 내부 YouTube 검색, 임의 공개 영상의 자동 자막 취득, 자동 교정 기능을 해결하지 않는다.

- 기술 참고: `captions.json`에 video ID와 `captions/<file>.srt/.vtt`를 매핑하면 기존 코드가 파일을 불러와 cue를 재생 시간에 맞출 수 있다.
- 권리 참고: Studio 다운로드 가능 여부가 외부 재배포 권한을 뜻하지 않는다. 공개 저장소에는 실제 권리자의 명시적 허가가 있는 파일만 둘 수 있다.
- 공식 안내: https://support.google.com/youtube/answer/2734705

## 일반 시청자용 자동 자막 취득 조사
- 현재까지 확인한 공식 경로에서는 일반 시청자가 볼 수 있는 YouTube 대본을 영상책이 읽어오는 API를 찾지 못했다.
- YouTube 공식 대본 화면은 사용자가 YouTube 안에서 읽고 문장별 이동을 하는 기능이며, 영상책에 대본 본문을 전달하는 API가 아니다.
- 상세 결과와 검증 한계는 [RESEARCH_BENCHMARKS.md §25](./RESEARCH_BENCHMARKS.md#25-일반-시청자-자막-자동-취득-공식-경로-재검증--2026-11-11)를 참조한다.


## 음성 인식 및 IFrame 자막 모듈 조사 기록
- 브라우저 Web Speech API는 자막 텍스트를 가져오는 기능이 아니라 마이크/오디오 트랙의 음성을 인식하는 별도 기능이다.
- Chrome의 기본 음성 인식은 서버 기반일 수 있고, Android Chrome에서 오프라인 on-device 인식 지원은 현재 호환성 자료상 확인되지 않는다.
- Android Chrome의 화면/시스템 오디오 캡처는 현재 호환성 자료에서 지원되지 않는 것으로 표시된다.
- YouTube IFrame API의 captions 모듈은 공식 문서상 자막 표시 크기 조정과 자막 데이터 새로고침 옵션만 노출한다. 자막 문장/대본 본문을 반환하는 옵션은 문서에 없다.
- 따라서 이 두 경로는 일반 시청자용 자동 자막 취득 핵심 기능으로 채택하지 않는다.
- 상세 근거: [RESEARCH_BENCHMARKS.md §26](./RESEARCH_BENCHMARKS.md#26-브라우저-stt와-youtube-iframe-captions-모듈-검증-2026-11-11).


## 자막 추출 생태계 조사 (VB-23)
여러 공개 구현과 사용자 사례를 비교한 결과, 공개 라이브러리 다수는 YouTube의 문서화되지 않은 내부 요청(InnerTube/timedtext)이나 페이지 스크래핑에 의존한다. 일부는 Node/Python/Go 런타임 또는 서버·프록시를 요구한다. 브라우저에서 YouTube 페이지 DOM을 읽는 사례도 있지만 사용자가 YouTube 대본 패널을 먼저 열어야 하며, 영상책의 별도 GitHub Pages 문서에서 임베드 iframe DOM을 읽는 방법은 아니다.
- 코드 참고 후보와 비채택 사유: [RESEARCH_BENCHMARKS.md §27](./RESEARCH_BENCHMARKS.md#27-공개-자막-추출-프로젝트-및-커뮤니티-사례-비교-2026-11-11).
- 공개 코드가 있다는 사실은 YouTube 접근 방식의 허가 또는 정책 준수를 의미하지 않는다.
- STT는 기존 자막 추출 경로 조사가 끝나기 전에 우선 검토할 주제가 아니었다. VB-22는 비채택 기록만 유지하고 핵심 탐색 우선순위를 대체하지 않는다.
